About ECDAT

ECDAT discovers every use of cryptography in a codebase and produces a Cryptography Bill of Materials (CBOM), so teams can plan the migration to post-quantum algorithms before harvest-now-decrypt-later attacks pay off.

How findings are graded

Quantum-broken (BROKEN_Q)

Public-key crypto that Shor's algorithm defeats outright — RSA, ECC, classic Diffie–Hellman. Highest migration priority; anything encrypted today can be harvested and decrypted later.

Weak today (WEAK)

Algorithms already broken or deprecated on classical hardware — MD5, SHA-1, DES, RC4. Replace regardless of quantum timelines.

Safe (SAFE)

Symmetric crypto and hashes that survive Grover's algorithm at adequate key sizes — AES-256, SHA-256 and up. No change needed.

Post-quantum (PQC)

NIST-standardised post-quantum algorithms — ML-KEM, ML-DSA, SLH-DSA. Already where you want to be.

Download & run offline

One click, no setup — no Python and no internet needed. First launch takes about 15 seconds to unpack, then ECDAT opens in your browser and scans your own code entirely on your machine.

First run
  • Windows: double-click ECDAT-windows.exe. If SmartScreen warns, click More info → Run anyway (the app is unsigned).
  • macOS: unzip, then right-click the ECDAT app → Open → Open. (It's unsigned, so a plain double-click is blocked the first time.)
  • Linux: unzip, then run ./ECDAT in a terminal (or make it executable and double-click).

Prefer to run from source? Download the source (needs Python 3.10+). All builds are on GitHub Releases.

Urgency: the Mosca inequality

A finding is marked urgent when the data it protects must stay secret longer than the time you have before cryptographically-relevant quantum computers arrive — Mosca's X + Y > Z. Urgent findings are flagged with an ! marker in the findings table and should lead your migration backlog.
